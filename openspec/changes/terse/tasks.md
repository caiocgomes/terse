## 1. Workspace and test execution contract

This checklist implements the existing [design](design.md), ten [capability specs](specs/), and [test plan](tests.md). All paths below are repository-relative implementation targets; the workspace, tests, fixtures, and application code do not exist yet. Use the standard Rust test runner and the two planned crates, without introducing a crate per compiler stage.

Work through five runnable milestones: first portable page (groups 2–5), one paper/two themes (6–10), multi-file scholarly paper (11–17), Git/editing workflow (18–21), and export/release (22–26). Each functional group starts with its tests, implements behavior, then reviews boundaries and reruns those tests. Follow the complete setup/assertion/edge-case contract in `tests.md`; do not replace it with weaker checks. Demonstrate behavioral Red after the harness compiles, then Green. Missing fixtures, undiscovered tests, and compilation failures are not behavioral Red evidence. If a referenced integration test needs a later group, continue that dependency and leave the earlier checkbox open until the complete referenced test passes.

The default verification command is `cargo test --workspace --locked`. Filter it by the exact referenced test names during a task; expect at least one discovered test and no failures. Heavy cases run with `cargo test --locked -p terse-cli --test e2e -- --ignored` in the pinned Linux environment. Milestone smoke runs supplement the mapped tests; full-paper and release gates remain open until their complete fixtures and assertions run. No checkbox in this file claims an existing implementation or a passing test.
